# vertical-flow 分支网格 + 便签左置 + 回归走线 设计

> 日期：2026-11-12 ｜ 状态：已批准并实施（dev `245fcc6`）｜ 归类：`docs/tech/`（红线 8）｜ 上游权威：`docs/tech/系统架构设计方案.md`
> 触发：易宝限额图（diag-mwdh7g7t-x01w）暴露两类观感缺陷；老板以手绘截图钉定目标几何。

## 一、意图与 Why

现状 vertical-flow 渲染器（`packages/shared/src/render/vertical-flow.ts`）有两处观感缺陷：

1. **便签压线**：附注列摆在主干右侧（`colX = trunkRight + BRANCH_GAP`），与 branch 走廊同侧，annotate 边与 branch 边都向右走，便签盒子压在 branch 横连线上。
2. **分支堆一条竖线**：`layoutBlock` 把 `next` 与 `branch` 子节点全部纵向堆叠，导致一个分支判定的两个结果（如「否→不限额」「是→限额」）叠在同一列，「是」边穿过「不限额」落到「限额」，读起来像顺序流程。

老板目标（手绘截图）：便签挪左；分支判定同行右置占整列；两个结果横向铺开占整行；「通过/继续」结果用**回归连线**连回派生它的主干节点；主干为分支行留空白、竖线保持干净。整体「一眼看懂」、降低 AI 出图试错成本。

## 二、目标 / 非目标 / 反目标

**目标**
- 附注列整体左置，右侧走廊完全留给 branch。
- 分支子树改「行/列网格」：next 下行、branch 右置；终端结果与 next 子同行横铺；继续型分支（decision/process）同行占新列。
- 回归边为**真实 spec 边**（复用 `loop` kind），分支→派生主干，横向回归走线。
- 主干为分支块预留整行空白，全局无节点重叠、无连线穿节点。
- 人机语义一致：MCP 描述 / normalize 校验 / 渲染 / 测试同步（红线 7）。

**非目标**
- 不改其他范式（timeline-annotated / swimlane / tiered-dag / tree）。
- 不新增 edge kind（不引入 `return`）。
- 不扩 apply_ops 的 handles/waypoints 入参（老板裁定②）。
- 不改锁保护 / 差量快照 / 批次账本逻辑。

**反目标**
- 回归边不得把「终端结果」画成「重试回环」语义：仅「通过/继续」结果回归，「限额」终端不回归；回归是 AI 显式 authored 的边，渲染器不自动补线。
- 不得共线覆盖分支出边、不得穿节点；回归与分支出边仅允许一个垂直 T 形汇流点。

## 三、约束

- 零注释、紧凑排版（红线 4）；确定性渲染（同 spec 同几何）。
- fixed/锁节点坐标零改写，其余让位（`avoid()` 保留）。
- 几何约定钉成可测量测试（视觉基准记忆）：无分支主干恒距 50、分支同行右置 85、回环侧路不穿主干、边显式连接桩。
- 验证环境：3000 live 服务不可重启，用隔离 env 实例；browser 面板未开时用结构/SVG 快照验收。

## 四、方案与取舍（已选方案 1）

- **方案 1（选定）网格化分支布局 + 显式回归边**：新增 `vertical-flow-grid.ts` 渲染器；回归复用 `loop`；normalize 开锚点例外；MCP/预设/测试同步。优点：语义显式、人机一致、复用契约、改动集中、旧渲染器保留供 timeline/swimlane 复用。代价：AI 出图需主动写回归边。
- **方案 2 渲染器自动补回归线**：AI 零负担，但画出 spec 不存在的连线，`get_diagram` 读不回，人机断层，且无法可靠区分该不该回归。**否决**。
- **方案 3 新增 `return` kind**：语义最干净但 schema/normalize/渲染/web/MCP/测试全链路加契约，改动面大，违背极简。**否决**（老板选 1）。

## 五、老板已裁定（不再翻案）

- 便签左置。
- 分支占整行/整列、结果横铺、主干留空白。
- 回归用真实 `loop` 边，终点=派生该分支的主干节点；仅通过/继续结果回归。
- 复用 loop kind（方案 1），不新增 kind。
- 恒距 50 降级为「仅无分支相邻主干恒距 50」，有分支行按块留白（Q5 确认）。
- 回归触发规则=「有双重判断的分支，其通过/继续结果回归」，含 o-pass 汇流点；授权修改 buildYeepaySpec（Q7 确认）。

## 六、几何约定（可测量，钉测试）

记 `trunkLeft/trunkRight` 为主干中心线 ± maxMainW/2；`midY` 为节点垂直中心。常量沿用 `constants.ts`，新增 `REG_LANE=24`、`REG_LANE_STEP=24`、`REG_STUB=12`、`GRID_COL_GAP=40`。

**G1 便签左置**：附注列从 `trunkLeft - BRANCH_GAP` 向左排布（多列继续左移）；annotate 边 `sourceHandle=left`、`targetHandle=right`，`midX = trunkLeft - BRANCH_GAP/2`。branch 左界不再受 annotRight 约束。

**G2 分支网格**：块内 (row,col) 递推——`next`→(row+1, 同 col)；`branch`→(col+1, row)，其中终端(start-end)分支子 row=源 row+1（与 next 子同行横铺），继续型分支子 row=源 row（同行占新列）。命名空间：占用格冲突时 col 顺移；列宽=该列最大节点宽，行高=该行最大节点高；节点左/上对齐于格。块左界=源节点右缘+BRANCH_GAP，块根 row0 的 midY == 源主干 midY（同行右置）。

**G3 主干留白**：主干 cursor 推进 = max(主干节点高, 分支块高) + MAIN_GAP，下一主干节点位于整个分支块下方。测试：下一主干.y ≥ 分支块底 + MAIN_GAP。恒距降级：仅无分支相邻主干恒距 50。

**G4 回归走线**（仅锚点回归情形，见 §7）：回归源为 row+1 的通过终端，其 midY 低于主干 row0，故水平出线不与 row0 分支出边共线。`sourceHandle=left`、`targetHandle=right`。lane 分配：每条回归边独立 lane，`laneX = trunkRight + REG_LANE + idx*REG_LANE_STEP`。waypoints =
`[(laneX, src.midY), (laneX, tgt.midY+REG_STUB), (trunkRight+REG_STUB, tgt.midY+REG_STUB), (trunkRight+REG_STUB, tgt.midY)]`。
回归竖桩在 `trunkRight+REG_STUB` 处与分支出边垂直 T 形汇流，末端短段共线入右桩视为汇流点（不视为遮盖）；不穿任何节点。branch/next 边仍由 web 路由器避节点，回归边用显式 waypoints。

**G5 重试回环不变**：target 严格早于锚点的 loop（含 main→main、branch→更早 main）沿用现有「上方侧路」走线与现有测试，不改。

**G6 全局**：noOverlap 恒真；所有边显式 sourceHandle/targetHandle；节点取 registry 尺寸。

## 七、契约改动

**normalize.ts**：loop 校验开锚点例外——当 `paradigm==='vertical-flow' && source.role==='branch' && target.role==='main' && regAnchor(source)===target` 时允许 `b===a`（regAnchor 沿 next/branch 上溯至主干）；其余 `b>=a` 仍报 SpecError（main 自环仍拒）。闭包防护：branch 节点发出 next/branch 指向 main 时 push warning（引导 AI 改用 loop 回归），不静默吞主干。

**范式隔离**：新增 `vertical-flow-grid.ts` 并由 `render/index.ts` 仅对 `vertical-flow` 分发；`timeline.ts`/`swimlane.ts` 继续复用旧 `renderVerticalFlow`，保持旧几何与旧测试（honoring 非目标）。

**mcp-server.ts**：scaffold 描述改为「无分支主干恒距、有分支按块留白、分支网格同行右置、回环上方侧路、分支通过结果 loop 回归源主干（横向侧路）、附注连续左列」；apply_ops 描述补 loop 回归约定。schema enum 不变（loop 已存在）。

**presets.ts**：第一个主模板 `flowchart-approval` 增加 comment 附注（note-1，attachTo dec-1）+ 显式 annotate 边演示左置；回归示例以 yeepay 测试 spec 承载。

**web**：复用 left/right 连接桩，registry/orthogonal-edge 无需改；copilot-planner 无布局文案 → 不改。
