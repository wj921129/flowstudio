# 页面巡检缺陷台账

> 逐页细节巡检（交互 / 功能 / 样式）的缺陷闭环 SSOT。由 leader 建档并维护，test 巡检汇报、front/back 修复、test 回归确认后更新状态。
>
> 团队分工：leader 拆解分派与台账维护 ｜ test 回归与轮次总结 ｜ front 前端修复 ｜ back 后端修复 ｜ reserve（Qoder）后备 + 提前巡检（流水线顺畅时承接下一轮提前巡检；任一成员意外失效时由 leader 移交其职责，后备优先）。

## 一、闭环流程

1. test 按轮次逐页实机巡检（浏览器真实操作，禁止仅读代码下结论）。
2. test 发现问题 → 向 leader 汇报（含复现步骤与证据）。
3. leader 登记缺陷编号（FS-xxx）并判定归属（front / back / 待定）→ 拆解任务分派。
4. front/back 修复 → 完成后汇报 test → test 回归：
   - 未通过：test 直接告知对应 front/back 继续修复（普通问题最多 1 次复审，严重 Bug 最多 3 次闭环）。
   - 通过：test 向 leader 汇报「FS-xxx 已解决」。
5. leader 更新台账状态 → test 进入下一轮巡检。
6. 每轮闭环后由 test 向 leader 汇报本轮总结，leader 归档至本台账「轮次记录」。
7. **持续运行直至收敛**：R1–R8 全部闭环后进入全量回归巡检（R9），重复整轮直至零新增 P0–P2 缺陷；P3 优化由 leader 酌情采纳。全程无需用户介入，leader 自动推进下一轮；任何成员遇阻塞立即上报 leader，不得静默停摆。
8. **提前巡检并行机制**：流水线顺畅时，leader 将下一轮巡检提前派给 reserve 执行，bug 汇报照常登记分派；test 专注当前轮回归与轮次总结，上一轮闭环后直接进入下一轮修复的回归，不再等待巡检结果。
9. **容灾降级（老板指示）**：4 名开发测试人员（front/back/test/reserve）中——1 人失效：reserve 移交接替；2 人失效：收缩为「1 开发 + 1 测试」最低档，开发兼前后端、测试兼巡检与回归，由 leader 按幸存成员能力统一改派，保证流程不停；3 人失效：停止全部任务，保留现场与台账，立即上报老板。提前巡检并行机制在降级期间暂停，恢复满员后再启用。
10. **共享设施纪律**：任何成员不得私自停止/重启共享服务（3000 后端等），需要时先报 leader 批准；收尾清理只动自己启动的进程与 scratch。环境异常（服务宕机、端口占用等）立即上报 leader 协调。共享 3000 一律分离式启动（Start-Process / start /b + 独立 stdout/stderr 重定向），勿绑定长驻服务父 shell/控制台，防进程组/会话终止连带宕机（两次宕机根因）。
11. **Context 轮换（老板指示）**：每轮任务闭环后，leader 确认闭环并归档台账，随后对承接下一任务的成员重置上下文（team_clear_agent_context），并重注入「职责卡 + 台账路径 + 当前任务状态」，确保职责不丢失、context 不无限增长；成员也可自行 /clear 清理。本台账为磁盘 SSOT，任何成员上下文重置后先读台账恢复状态再开工。重置须在成员空闲时执行（运行中会失败）；若成员已接续下一任务，则顺延至该轮汇报后的空闲窗口轮换，不打断进行中工作。若重置工具在成员运行后端不可用（报错），改令成员自行 /clear 清理后读台账恢复状态，职责经台账 + 重注入消息保证不丢失。
12. **Leader 自身 context 管理（老板指示）**：每轮闭环后 leader 更新「六、leader 状态快照」，将进行中事项、待触发点、关键 ID 落盘；leader context 被清理或自动压缩后，先读本台账（含状态快照）无损恢复职责。老板可随时对 leader 执行 /clear，不影响流水线（成员任务与台账均持久化）。
