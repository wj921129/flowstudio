# FlowStudio 架构演进与健壮性优化规格说明书

> 日期：2026-11-18 ｜ 状态：待评审确认 ｜ 关联工单：[架构演进与健壮性优化工单拆解](./2026-11-18-架构演进与健壮性优化工单拆解.md)

---

## 1. Problem Statement（问题陈述）

FlowStudio 已完成基础的多人实时协作画布（React Flow + Yjs + Hocuspocus + SQLite）与人机共治 MCP 链路（`scaffold_diagram` / `apply_ops` / `undo_ai_batch`），但在架构健壮性、数据安全、人机并发边界与大图扩展性方面存在关键隐患：

1. **数据安全与持久化隐患**：超过 2MB 的图状态在后台重构为全新随机 `clientID` 的 `Y.Doc` 后，又与旧状态执行 `Y.mergeUpdates`，破坏了 CRDT 因果血缘并丢失删除墓碑，导致重启后已删实体复活或状态回退；压缩、事务补偿与快照恢复均遗漏 `comments` 共享容器，导致大图批注永久丢失；服务进程退出时未刷新 Hocuspocus 防抖窗口即关闭 SQLite，存在数据丢失风险；外部 Draw.io/XML 导入缺乏解压字节上限与畸形防护。
2. **人机协同并发与原子性缺失**：MCP 的 `apply_ops` 遇错仅记警告继续执行，造成半残画布并污染空批次账本；`auto_layout` 与 `scaffold_diagram` 在读取与异步排版后才写入，间隙内人工修改可引发空指针崩溃或锁被覆盖；`undo_ai_batch` 撤回删改时未校验端点、父容器及人工子节点的拓扑完整性；AI 全程未广播服务端 Awareness，协作者无法感知 AI 的编辑状态。
3. **前端状态同步回环与大图性能瓶颈**：所有局部画布编辑均通过整图 `setDiagram` 写回且监听端忽略 `origin` 与局部变更做全量重建，引发双倍渲染与并发覆盖；拖拽期间未锁定本地坐标且在协同模式下仍同步 `structuredClone` 全图快照；高频移动光标通过 Context 穿透重渲染全画布，且正交避障路由在渲染期全量同步计算。
4. **契约分裂与巨型模块耦合**：`ai-collaborator`（1814 行）与 `flow-store`（2039 行）职责过载；节点类型枚举在共享契约、MCP Schema 与前端组件注册表间多处手写重复且已发生漂移；`node.data` 作为整包对象存入 Yjs 导致多端修改不同属性互相覆盖；工程缺少统一的 `schemaVersion` 迁移机制与自动化校验门禁。

---

## 2. Solution（解决方案）

在不破坏既有局域网单进程极简部署形态与人机共治核心语义的前提下，分四层递进加固底座：

1. **守住数据零丢失底线**：停止在运行时用无血缘新文档重建状态后再合并的做法，改以 Yjs 原生增量合并配合一次性离线 Epoch 迁移机制；将 `comments` 纳入全局顶层共享容器清单统一受事务补偿、快照恢复与迁移保护；补齐服务优雅停机刷新、房间驱逐、WS 帧熔断、外部解析上限与前端分级错误边界。
2. **建立严格的人机协同事务语义**：为 `DocumentWriter` 引入按图串行化写入队列与写前存在性/锁二次校验；为 `apply_ops` 提供原子执行模式、空批次零污染过滤与自纠型 JSON Schema；完善批次撤回的拓扑引用检查；让 AI 操作通过服务端 Awareness 在画布上可见。
3. **打通前后端细粒度增量同步**：前端常规操作直连 `YjsDiagramBridge` 节点/连线级增量接口，监听端按 `origin` 与变更键局部替换引用；拖拽期隔离远端位移并取消协同模式冗余深拷贝；拆分高频感知通道与空间索引路由，支撑千级图元流畅协作。
4. **收口单一事实源与模块边界**：通过 `FLOW_NODE_TYPES` 与 `NODE_REGISTRY` 自动派生后端校验与前端强类型约束；建立数据库与 Y.Doc 的幂等版本迁移器并将 `node.data` 拆分为嵌套共享映射以消除并发字段覆盖；将巨型核心拆分为职责单一的子模块与 Slice，补齐构建解析一致性与自动化测试门禁。

## 3. User Stories（用户故事）

### 数据安全与可靠性（协作者 & 管理员）
1. 作为一名协作者，我希望超过 2MB 的大图在自动保存或重新打开后，所有已删除节点保持删除、已修改属性保持最新，不会因为后台状态压缩而复活旧节点或回退编辑。
2. 作为一名协作者，我希望大图上的画布批注与评论在经历持久化、服务端重启或历史快照恢复后完整保留，不会被静默清空。
3. 作为一名系统管理员，我希望服务端在收到退出信号（如 Ctrl+C 或进程终止信号）时，先断开连接并把内存中尚未落库的防抖编辑全部写入数据库后再关闭数据库连接，确保最后两秒的协作不丢失。
4. 作为一名协作者，我希望使用历史快照恢复功能时，快照之后新增的多余节点属性（如后来误拖入泳道的父容器绑定）被彻底清除，而未变化的节点不会生成冗余的历史冲突记录。
5. 作为一名协作者，我希望在另一名成员删除某张图表后，所有正在查看该图的客户端立即收到会话结束提示并断开连接，不会在“幽灵画布”上继续编辑而误以为已自动保存。
6. 作为一名协作者，我希望打开无效或已被删除的图表协同连接时被服务端直接拒绝，而不是在内存中创建一个无法保存的空房间。
7. 作为一名协作者，我希望在导入畸形或恶意构造的 Draw.io、BPMN 或 Mermaid 文件时，系统能够及时拦截并给出明确错误提示，不会导致浏览器标签页崩溃或服务端内存耗尽。
8. 作为一名协作者，我希望当单个异常节点或正交连线渲染出错时，界面仅局部降级并保留重试与紧急导出画布数据的入口，而不是整页白屏丢失当前工作。

### 人机共治协同（AI Agent 开发者 & 协作者）
9. 作为一名调用 MCP 的 AI Agent，我希望 `apply_ops` 支持原子事务语义：当编排的一组连线或结构操作中任意前置步骤失败时，整个批次完整回滚，不留下半残画布，且零有效变更时不写入空批次账本或多余快照。
10. 作为一名调用 MCP 的 AI Agent，我希望当传入非法参数、缺少必填字段或引用不存在的端点时，工具描述能清晰展示所有 `op` 的完整字段规范，且报错信息包含可直接用于自我修正的提示。
11. 作为一名协作者，我希望在 AI 执行耗时较大的自动排版或骨架生成期间，如果我同时删除了节点或加上了位置锁定，AI 写入前能自动感知最新画布状态并让位于我的锁，而不是导致服务端崩溃或覆盖我刚锁定的位置。
12. 作为一名协作者，我希望在画布上能实时看到 AI 是否在线、是否正在规划布局以及正在修改哪些节点（如同人类协作者的光标与头像），避免我与 AI 同时编辑同一个区域。
13. 作为一名协作者，我希望在撤回 AI 批次时，如果 AI 新建的泳道内已经被我手动拖入了业务节点，或者 AI 曾删除的连线端点已经被我彻底删掉，系统能够智能跳过并保留正确结构，不制造孤儿节点或悬挂幽灵边。
14. 作为一名协作者，我希望部分撤回后的 AI 批次如果仍有未受人工冲突的残留操作，再次触发默认撤回时能继续清理剩余项；若撤回由 `scaffold_diagram` 生成的图，连同范式与标题元数据也能正确还原或受控处理。
15. 作为一名协作者，我希望当我修改某个节点的背景色而 AI（或同事）同时修改同一节点的文字标签时，双方的修改都能同时生效，不会因整包覆盖而丢失其中一方的改动。

### 高流畅度实时协作（画布用户）
16. 作为一名协作者，我希望我在拖拽节点的过程中，同事或 AI 对画布其他部分的编辑不会把我正在拖动的节点弹回原位，且我松手后仅提交我的位置变动，不会覆盖同事刚刚新增或删除的图元。
17. 作为一名协作者，我希望在包含 1000 个以上节点和连线的大图中移动单个节点、缩放或平移画布时依然跟手流畅，不因本地修改触发全量图表重建、深拷贝历史或全画布渲染而卡顿。
18. 作为一名协作者，我希望同事频繁移动鼠标光标时，画布上的节点和连线组件本身不会反复重渲染。
19. 作为一名协作者，我希望切换到另一张图表后，上一张图的正交避障缓存、路由状态与定时器被彻底清理，新图的连线避障不会受历史图表残留障碍物干扰。
20. 作为一名协作者，我希望执行主题切换后按撤销快捷键（Ctrl+Z），能够连同画布颜色和当前激活的主题标识一并撤销，不出现节点样式回退而主题选择器仍停留在新主题的撕裂现象。
21. 作为一名离线断网后短暂编辑的协作者，我希望在网络恢复前刷新页面也不会立刻丢失本地尚未同步的增量改动，并在重连后自动清除已被同事删除的悬空选中态。

### 可扩展性与工程底座（项目维护者）
22. 作为一名维护者，我希望新增一种节点类型时，只需在共享注册表与契约中定义一次，后端 MCP 校验、前端组件映射校验、导出与互操作映射就能通过编译期检查自动对齐或暴露遗漏。
23. 作为一名维护者，我希望使用 UML、架构图及富文本卡片等新图元绘制的图表在导出为 SVG、PNG 或离线 HTML 时保留其专属图形与内容，而不是全部退化为普通矩形。
24. 作为一名维护者，我希望历史存储的数据库表结构或 Y.Doc 共享数据结构未来需要升级时，有显式的版本号与幂等迁移流水线自动完成平滑升级。
25. 作为一名维护者，我希望项目拥有统一的静态检查与自动化验证门禁，测试按业务功能域清晰组织，且在修改共享包代码后服务端与前端都能实时引用最新契约而无构建产物错位。

## 4. Implementation Decisions（实现决策）

### 4.1 持久化、压缩与停机生命周期（服务端）
- **废除运行时无血缘重构压缩**：由于前端已实现字段级增量写入（消除整图重写带来的 CRDT 历史爆炸），运行时不再使用新建随机 `clientID` 的 `Y.Doc` 重建状态并送入 `Y.mergeUpdates`。保留一次性离线清理/压缩能力，若对存量膨胀文档执行离线清洗，需递增 `meta.docEpoch` 并由服务端在客户端携带旧 epoch 同步时触发重新初始化同步，彻底隔离新旧血缘合并。
- **共享容器统一注册表**：定义顶层共享 Map 常量集合（包含 `nodes`、`edges`、`meta`、`comments`），所有涉及全域操作的服务端路径（`DocumentWriter` 事务补偿作用域 `Y.UndoManager`、`applySnapshotDelta` 快照差量对比、离线迁移扫描）均遍历此注册表，严禁硬编码子集。
- **差量快照恢复精确语义**：`applySnapshotDelta` 对比当前文档与目标快照时，必须同时删除目标快照中已不存在的实体内部子字段，且仅在 `deepEqual` 为 `false` 时写入变更键，避免未变字段产生冗余 CRDT 操作日志。
- **优雅停机与资源生命周期**：
  - 进程层监听 `SIGINT` 与 `SIGTERM` 并触发服务实例关闭。
  - 服务关闭钩子按序执行：停止定时快照调度器 → 主动断开全部协同 WebSocket 连接 → 调用 `hocuspocus.flushPendingStores()` 并等待所有在途落库完成后再关闭 SQLite 连接。
  - 删图接口在删除持久化行前强制关闭对应 `documentName` 的在线房间连接，并清理 `SaveStatusTracker` 等内存映射；WebSocket 建连与文档加载校验图表存在性并配置合理的 `maxPayload` 上限。
- **数据库与文档迁移基础设施**：
  - 数据库层基于 `PRAGMA user_version` 建立幂等迁移序列，并复用预编译 Statement 句柄；定期清理超限的自动快照并限制定时快照仅扫描 `updated_at` 推进的图表。
  - Y.Doc `meta` 引入 `schemaVersion` 标识，支持在文档加载或写入前执行无损幂等结构迁移。

### 4.2 外部互操作解析安全与导出对齐（共享包 & 前端）
- **输入与资源熔断**：所有互操作解析入口（Draw.io、BPMN、Mermaid）统一强制前置原始文本大小上限与最大节点/连线数量熔断；Draw.io 解压改用流式读取并累计解压字节数，超限立即中止；XML 解析拒绝 `<!DOCTYPE`/`<!ENTITY` 声明并校验码点处于合法 Unicode 标量区间；计算父子绝对坐标时使用邻接索引并做访问集合环检测。
- **布局边界修复**：共享布局器中保留 `fixed` 锁定节点的纵横坐标不被行高覆写；分支网格与分层布局预建节点索引并补充成环检测与固定节点避让。
- **渲染一致性**：对齐 SVG/PNG 与离线 HTML 导出引擎，覆盖全部已注册图元族（流程图、泳道、UML、架构图、富文本卡片）。

### 4.3 人机协同事务与感知架构（MCP & `DocumentWriter`）
- **按图串行写入队列**：`DocumentWriter` 为所有异步或跨步骤变更提供按 `diagramId` 隔离的串行化执行队列。凡是包含“读取 → 异步计算（如 ELK 排版）→ 写入”的复合操作，必须在提交事务内重新核查目标节点/泳道的当前存在性与最新锁定模式（`lockMode`）。
- **`apply_ops` 事务与自纠契约**：
  - `apply_ops` 支持原子执行（默认推荐开启原子模式，或通过显式 `atomic: boolean` 参数控制）：参数校验、存在性校验及非锁类约束失败时抛出异常触发 `DocumentWriter` 事务补偿回滚，保障画布不出现半残状态；若全批次有效变更数 `appliedCount === 0`，跳过前置快照生成与空批次记账。
  - 取消 `mcp-server` 中手工维护的模糊 `object` Schema，统一使用 `z.toJSONSchema` 从共享与操作 Zod Schema 自动推导全量工具入参描述，为单次 `ops` 数组设置上限（如 200），并对所有 MCP 工具入参实施强校验与结构化自纠错误返回。
  - 清理已从工具清单下线的死接口。
- **批次撤回拓扑完整度**：`AiBatchManager` 撤回操作时执行三项拓扑护栏：恢复被删边前确认两端节点存活；恢复被删节点前确认 `parentId` 存活（否则降级剥离父引用）；删除 AI 新建容器前检查内部是否存在人类新增或移入的子节点。`undo_ai_batch` 默认查找覆盖存在可撤回残余项的 `partially_reverted` 批次。
- **服务端 AI Awareness**：封装短生命周期的服务端感知状态注入机制，在 AI 规划与写入期间向协同房间广播：
  ```ts
  // 语义契约原型（源自 shared 既有 UserAwarenessState 扩展约定）
  {
    isAi: true,
    agentName: string,
    aiPlanning: boolean,
    selectedNodeIds: string[], // AI 当前正在读写的目标节点集
  }
  ```

### 4.4 前端状态同步、性能优化与容错（Web）
- **单一数据源与双向局部同步**：
  - 常规画布写动作（移动、改文本、改样式、增删单个节点/连线、移入泳道）改由 `YjsDiagramBridge` 的细粒度增量 API（`patchNode` / `patchNodes` / `putNodes` / `removeNodes` / `patchEdge` / `removeEdges`）直接提交；`setDiagram` 仅保留给整图导入与模板覆写。
  - `YjsDiagramBridge` 监听回调区分 `transaction.origin === localClientId`，跳过本地触发的二次全图重算，并依据 `YMapEvent.changes.keys` 进行局部对象引用更新；多级容器按树深度拓扑排序确保父容器先于子节点。
  - 交互态隔离：节点拖拽中（`isDraggingOnly`）接收远端更新时保留被拖拽节点的本地坐标与拖拽态，松手仅增量 patch 位移与吸附变化。
- **渲染与历史性能解耦**：
  - 协同模式下禁用每次操作全图 `structuredClone` 的本地历史快照维护；将 `meta` 纳入协同 `Y.UndoManager` 跟踪范围，移除每次提交的无条件 `stopCapturing()` 以恢复合理的合并撤销窗口。
  - 将高频变更的 `remoteUsers` 从 `CollaborationContext` 剥离为独立外部订阅源，防止光标移动穿透重渲染全画布；`EdgeRoutingManager` 引入空间网格/包围盒索引与视口外延迟重排，并在切图卸载时强制清空单例状态。
  - 为 `App` 与画布工作区装配分级 `ErrorBoundary`，在渲染崩溃时提供局部恢复与本地 JSON 导出保底。
- **状态与逻辑模块拆分**：
  - `ai-collaborator` 拆分为：`diagram-query-service`（只读查询与局部检索）、`ops-executor`（命令分发映射与内存图索引）、`layout-engine`（ELK 与泳道几何推挤）、`semantic-inspector`（图结构巡检）及轻量编排门面。
  - `flow-store` 拆分为：`graphSlice`、`interactionSlice`、`historyCollabSlice`、`uiOverlaySlice`，消除模块级可变全局桥接句柄。
- **嵌套协同结构升级**：通过 `schemaVersion` 迁移器将 `node.data` / `edge.data` 由整包扁平值演进为嵌套 `Y.Map`（至少将易并行冲突的 `label`、业务元数据与 `style` 键分离），使人类改样式与 AI 改文本可无冲突合并。

### 4.5 单一事实源与工程治理
- **契约自动派生**：`FlowNodeType` 与相关枚举由 `FLOW_NODE_TYPES` 单一数组推导；后端 `op-schemas` 与 `McpOp` 类型由共享列表与 `z.infer` 派生；前端节点组件映射表强制采用 `satisfies Record<FlowNodeType, ...>` 编译期穷尽检查。
- **Monorepo 构建一致性**：为共享包开启 TS Project References（`composite: true`），统一开发与编译期解析路径，避免服务端读取过期构建产物。
- **工程门禁与测试整理**：配置轻量级 Lint 与基础 CI 检查，将按历史轮次命名的测试文件重组归位至对应的业务能力测试集中。

## 5. Testing Decisions（测试决策）

### 测试哲学（最高接缝原则）
所有验证聚焦于**模块公共契约与外部可观测行为**（持久化数据库终态、WebSocket 同步广播结果、MCP 工具返回与画布真实状态、前端 Store/画布用户交互结果），禁止断言内部私有方法或具体实现结构，确保后续模块拆分重构期间测试无需大面积重写。

### 关键测试接缝（Seams）
1. **持久化与协同服务端接缝**：以 `buildServer` + 真实内存/临时 SQLite + 真实 `Y.Doc` / WebSocket 连接（或 `DocumentWriter` 公共 API）作为最高测试接缝，验证：
   - 大图与含批注文档在重启加载、停机 `app.close()`、删图驱逐及快照恢复后的最终状态一致性（无复活、无丢失、无多余属性残留）。
   - 并发写入场景（人工修改 + 异步排版 / MCP `apply_ops` / 批次撤回）的串行语义、原子回滚与拓扑安全性。
2. **MCP 工具契约接缝**：以 MCP JSON-RPC `tools/list` 与 `tools/call` 处理器作为唯一接缝，验证参数 Schema 完整性、畸形参数自纠提示、`appliedCount === 0` 不落账与 AI Awareness 状态可见性。
3. **互操作解析接缝**：以 Draw.io / BPMN / Mermaid 桥接器公开转换函数作为接缝，验证压缩炸弹字节熔断、非法 XML 实体/父子环拦截及新图元导出保真度。
4. **前端协同与交互接缝**：以 `YjsDiagramBridge` 搭配本地/远端双 `Y.Doc` 同步及 React Testing Library / Store 公开动作作为接缝，验证：
   - 本地增量写入不触发冗余全量回灌、远端并发不打断拖拽位置、多级泳道拓扑序正确、切图清理路由缓存、ErrorBoundary 捕获异常节点后不白屏。

### 既有测试先例（Prior Art）
沿用仓库内已有的端到端与集成测试模式：服务端协同测试（`e2e-collaboration`、`ai-batch`、`field-level-rollback`、`snapshots`、`mcp-tools`）、共享互操作与渲染测试（`interop`、`mermaid-bridge`、`render-*`）以及前端集成测试（`store-yjs-integration`、`yjs-doc-bridge`、`undo-manager`、`multi-diagram-isolation`）。

## 7. Further Notes（补充说明：待老板拍板的 3 项关键决策）

1. **运行时压缩机制处理方式**：
   - *推荐*：下线运行时无血缘新文档重构压缩，保留离线一次性迁移脚本 + `meta.docEpoch` 机制（从根源杜绝 CRDT 血缘破坏）。
   - *备选*：保留运行时压缩，但落库改为 CAS 版本校验覆写（仍有旧客户端离线重连时携带历史合并的风险）。
2. **`apply_ops` 原子事务默认行为**：
   - *推荐*：默认开启原子模式（除锚定锁跳过外，任一逻辑错误整批回滚并明确返回失败，便于 LLM 自纠）。
   - *备选*：默认保持兼容（局部跳过返回 `warnings`），仅当调用方传 `atomic: true` 时开启全回滚。
3. **测试接缝确认**：请确认第 5 节提出的 4 处最高测试接缝是否符合您对架构演进阶段回归验证的预期。
