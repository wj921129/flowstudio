# 空 ydoc 图陈旧缩略图数据卫生迁移记录（FS-043）

## 一、成因定位

1. **前端陈旧上报路径**：`packages/web/src/app/app.tsx` 缩略图同步 effect 在 `nodes.length === 0` 时直接 `return`，清空画布或恢复空快照后永远不会向服务端写入空缩略图，历史缩略图长期滞留。
2. **服务端写入路径从不维护缩略图**：MCP `apply_ops` / AI 批次撤回 / 快照差量恢复等经 `DocumentWriter.mutate` 的写入，以及 Hocuspocus `onStoreDocument` 落库，均只写 `ydoc_state`，文档被清空时缩略图保持原样。
3. 缩略图由前端每 2s 防抖 `PATCH /api/diagrams/:id` 生成上报，服务端不生成缩略图，故无「空文档自动再生空图」的兜底。

## 二、代码修复（防未来脏数据）

- **前端** `app.tsx`：缩略图防抖 effect 增加 `isSynced` 门禁（避免首屏未同步时误清空），同步完成后空画布主动上报 `thumbnail: ''`，有节点时照旧生成 SVG。
- **服务端** `SqlitePersistenceExtension.onStoreDocument`：成功落库后若 Live Doc `nodes` 为空，同步 `clearThumbnail`（覆盖客户端清空/离线关闭场景）。
- **服务端** `DocumentWriter.mutate`：在线 / 直连 / 离线三条写入路径成功后若 `nodes` 为空，同步清空缩略图（覆盖 MCP 与快照恢复等无浏览器场景）。
- 清空缩略图仅执行 `UPDATE diagrams SET thumbnail = ''`，**不触碰 `updated_at`**，看板排序不受影响。

## 三、一次性定向迁移

- 迁移函数：`packages/server/src/db/thumbnail-hygiene.ts` → `clearStaleEmptyThumbnails(repo)`。
- 判定条件（严格定向）：ydoc 解码后 `nodes.size === 0` **且** 缩略图非空；解码异常一律跳过不动。
- 备份（迁移前）：`C:\Users\63196\AppData\Local\Temp\flowstudio-db-backup-FS043-2026-11-14T00-55-18-834Z\flowstudio.sqlite`（495,616 B，better-sqlite3 在线备份 API，快照已包含 WAL 内容）。回滚方式：停止 3000 服务后以该文件覆盖 `data/flowstudio.sqlite` 并删除 `data/flowstudio.sqlite-wal/-shm`，再重启（停/重启需先报批 leader）。
- 执行方式：临时脚本调用编译产物，服务保持运行（WAL 并发写，未停 3000）；脚本用后已删除。
