# 保存状态信号契约（FS-033 back）

> 面向前端消费方：保存指示器、Ctrl+S 手动保存、定时快照可见性。服务端实现已完成并通过全量测试。

## 一、通道选型

采用 **REST 轮询**（最简成熟方案），不改协同 WS 协议、不新增 awareness 字段：

- 读：`GET /api/diagrams/:id/save-status`
- 写（手动保存）：`POST /api/diagrams/:id/save`
- 快照创建仍复用既有 `POST /api/diagrams/:id/snapshots`（不重复造端点）

共享类型：`SaveStatusSummary`（`@flowstudio/shared`，`packages/shared/src/types.ts`）。

## 二、响应契约

### GET /api/diagrams/:id/save-status

```json
{
  "diagramId": "uuid",
  "lastSavedAt": "2026-11-14T08:00:00.000Z",
  "lastSnapshotAt": "2026-11-14T07:55:00.000Z",
  "nextSnapshotAt": "2026-11-14T08:05:00.000Z",
  "snapshotIntervalMs": 300000,
  "serverTime": "2026-11-14T08:00:03.000Z"
}
```

| 字段 | 类型 | 语义与触发时机 |
| --- | --- | --- |
| `lastSavedAt` | `string \| null` | 最近一次成功落库（SQLite `ydoc_state`）时间。由 `onStoreDocument`（Hocuspocus 防抖落库）或 `POST /save` 成功后写入内存并取当前时间；服务重启后本次进程无记录时回退为图表 `updatedAt`（含改名等元数据更新，属近似值） |
| `lastSnapshotAt` | `string \| null` | 最近一次快照创建时间，任意触发类型（manual / ai_batch / auto / timer），取快照列表首条 |
| `nextSnapshotAt` | `string \| null` | 下一次定时快照巡检（timer tick）时间；调度器未运行时为 `null`。注意：tick 时内容无变化不会产生新快照，故该时间表示「下次检查」而非「必定出新快照」 |
| `snapshotIntervalMs` | `number \| null` | 定时快照周期，默认 `300000`（5 分钟）；未装配调度器时为 `null` |
| `serverTime` | `string` | 服务端当前时间，用于校正局域网客户端时钟偏差（倒计时请基于 `nextSnapshotAt - serverTime` 计算） |

不存在的图表返回 `404 { error: '图表不存在' }`。

### POST /api/diagrams/:id/save（手动保存）

- 无请求体。
- 在线文档存在时：**跳过防抖窗口立即落库**，刷新 `lastSavedAt`，返回 `flushed: true`。
- 冷文档（无在线连接）：无需写库，`flushed: false`，直接回传当前状态。

```json
{ "success": true, "flushed": true, "status": { /* SaveStatusSummary */ } }
```

不存在的图表返回 `404`。

## 三、前端消费建议

1. 进入图表后拉取一次；页面可见期间每 5s 轮询一次即可（LAN 开销可忽略），`document.visibilityState !== 'visible'` 时暂停。
2. 保存状态机（前端本地推导）：
   - `编辑中`：本地存在未同步/未保存改动（本地编辑时间 > `lastSavedAt`）；
   - `保存中`：WS 已同步（`已同步` 态成立）但 `lastSavedAt` 尚未推进（防抖 0.5s~2s 窗口）；
   - `已自动保存 · 上次保存于 HH:MM`：`lastSavedAt` 已推进到本地编辑之后。
3. Ctrl+S / Cmd+S：`preventDefault()` → `POST /save` → 用返回的 `status.lastSavedAt` 立即刷新指示器并 Toast「已保存」；不必等待下一轮轮询。
4. `nextSnapshotAt` 为 `null` 时不展示定时快照倒计时；否则可用 `serverTime` 校正后展示「下次自动快照 HH:MM / 倒计时」。

## 四、MCP 联动红线评估

- 本次仅新增**只读状态查询**与**强制落库**，不改变 `apply_ops` / `scaffold_diagram` / `auto_layout` / 快照恢复的 ops 语义与差量契约。
- 手动保存与 Hocuspocus 防抖落库共用 `saveYDocState` 的 CRDT 增量合并路径，无整包覆盖风险。
- 结论：**无 MCP 工具新增/改造需求，红线未触碰**。
