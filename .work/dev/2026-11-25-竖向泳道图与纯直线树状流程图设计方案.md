# 设计文档：竖向泳道图扩展、横向泳道走向修复与纯直线树状流程图

## 一、意图与场景
1. **真实业务侧（竖向泳道图）**：按角色/端分列（客户端、服务端、业管端等），展示跨端业务真实流转，自上而下按因果时序推进。
2. **真实代码侧（纯直线树状流程图）**：以指定接口/业务为入口，从上到下像大树一样逐层展开内部业务处理、数据库交互、外部服务调用，支持多步骤共享同一张表/外部服务的汇聚结构。
3. **缺陷修复**：修复现有 MCP/Spec 生成横向泳道图时，跨泳道节点被错误竖排挤在最左侧的 Bug，以及既有纵向泳道的 40px 坐标错位和切向不重排问题。

## 二、目标 / 非目标 / 反目标
- **目标**：
  1. 竖向泳道图人机全链路打通（`DiagramSpec` → 渲染器 → 画布拖拽/加泳道/切向/自动排版 → 模板库 → MCP）。
  2. 横向与竖向泳道统一为对称的「全局因果层号 → 泳道投影」确定性引擎，根治横向跨泳道竖排 Bug。
  3. 纯直线路由（`straight`）全链路打通（Spec 图级/边级、MCP `apply_ops`、属性面板切换、导出兼容）。
  4. 升级 `tree` 范式为「树优先分层布局」，支持完整流程/代码语义、多父汇聚节点，并抽成前后端共享的树状自动排版引擎 + 代码侧纯直线模板。
- **非目标**：不引入贝塞尔曲线路由；不改动 `pool → lane → node` 嵌套模型；不改 `vertical-flow` / `timeline-annotated` / `tiered-dag` 默认排版；不做跨多个泳道池联合排版。
- **反目标**：跨泳道连线倒流；纵向泳道覆盖顶部 40px 池表头或左侧空出 40px 缝；代码调用树遇共享表/服务报错或重复节点；破坏现有锚定锁（`position`/`full`）、AI 批次撤回或单主干横向泳道图兼容性。

## 三、方案选型
- **方案一（已选）：正交扩展现有体系**——复用 `swimlane` 和 `tree`，新增 `orientation?: 'horizontal' | 'vertical'` 与 `edgeRouting?: 'orthogonal' | 'straight'`（及单边 `routingType`）。人机双侧单一真相源，直线能力可跨全图复用，画布一键切向与 Spec 语义不冲突。
- **方案二（弃选）：新增 `vertical-swimlane` + `straight-tree` 独立范式**——画布切向时与 `paradigm` 语义漂移，直线被绑死在特定范式，长期维护双套重复代码。
- **方案三（弃选）：委托 ELK 统一排版**——ELK `layered` 无法保证大树对称居中，且难与确定性差量渲染及锚定锁严密配合。

## 四、核心设计

### 1. 契约扩展（`packages/shared`）
- `DiagramSpec` / `diagramSpecSchema` / `NormalizedSpec`：
  - 新增 `orientation?: 'horizontal' | 'vertical'`（默认 `'horizontal'`，用于 `swimlane`）；
  - 新增 `edgeRouting?: 'orthogonal' | 'straight'`（默认 `'orthogonal'`，图级默认路由）；
  - `SpecEdge` 新增 `routingType?: 'orthogonal' | 'straight'`（单边覆盖）。
- `normalizeSpec` 放开语义边界：
  - `swimlane`：允许跨泳道 `branch` 边，允许 `annotate` 挂在 `branch` 节点上，放宽 `loop` 校验以支持跨泳道与分支回流；
  - `tree`：取消「必须且仅能使用 `kind: 'tree'`」与「禁止多父节点」限制，支持 `tree`/`next`/`branch`/`annotate`/`loop` 边与多父汇聚（DAG），仅禁自环；遇非 `loop` 有向环时告警、破环分层并**保留该回边**（走侧路连接桩）。

### 2. 泳道对称排版引擎与缺陷修复（`shared` + `server` + `web`）
- **统一坐标系铁律**：
  - 泳道池表头固定在顶部 `headerSize = 40`；
  - 横向池：泳道从 `(x=0, y=40)` 自上而下堆叠，泳道左侧表头宽 40px，子节点局部避开左侧表头；所有泳道等宽 `pool.width`，`pool.height = 40 + sum(lane.height)`；
  - 竖向池：泳道从 `(x=0, y=40)` 自左向右并排，泳道顶部表头高 36px，子节点局部避开顶部表头；所有泳道等高 `maxLaneH`，`pool.height = 40 + maxLaneH`，`pool.width = sum(lane.width)`。
- **渲染器重构（`packages/shared/src/render/swimlane.ts`）**：
  - **单泳道特例保留**：仅当 `orientation === 'horizontal'` 且所有非附注节点（`main` + `branch`）同处一条泳道时，沿用 `renderHorizontalTrunk`（完全兼容现有单主干+上下依赖泳道图）；
  - **通用跨泳道对称引擎（覆盖横向跨泳道修复 + 全部竖向泳道）**：
    1. 忽略 `loop` 与 `annotate` 边，按最长路径为所有非附注节点分配全局因果层号 `layer(v)`（严格逐层递进，杜绝倒流）；
    2. 同 `(layer, lane)` 多节点沿泳道副轴顺次排开（横向撑高泳道、竖向撑宽泳道）；
    3. 汇总每层最大主轴跨度累加全局主轴坐标，投影为各泳道内局部坐标（横向推进 X、竖向推进 Y）；
    4. 附注节点紧随宿主主轴坐标落位并避让重叠；
    5. 同泳道正向沿主轴连接桩（横向 `right→left`，竖向 `bottom→top`），跨泳道正向按目标方向择优连接桩（`loop` 走侧路），最终经 `distributeEdgePorts` 统一端口防重叠。
- **既有纵向池 Bug 与锁冲突修复**：
  - `pool-node.tsx`：`handleAddLane` 纵向 `currentRight` 初值由 `headerSize` 改为 `0`；
  - `lane-nesting-manager.ts`：纵向扩容 `headerSize` 计入 `poolTotalH` 而非 `poolTotalW`；`reorderPoolOrientation` 切向时重投影泳道内子节点局部坐标、清除旧手动 `waypoints` 并刷新端口；
  - `elk-layout.ts` & `swimlane-geometry.ts`：纵向泳道统一从 `(x=0, y=headerSize)` 起排；
  - `diagram-auto-layout.ts`：未显式指定 `direction` 且图含纵向泳道池时自动默认 `DOWN`；
  - `spec-ops.ts` & `diagram-scaffolder.ts`：同方向二渲沿用现有保护人工泳道位置的契约；仅当切换池方向时更新未锁定容器坐标与尺寸，且方向变更时丢弃旧方向 `laneSizes`；若池内含任意 `position`/`full` 锁定节点，切方向操作（MCP 与画布按钮）整池拦截并提示/告警，防止横纵混排损坏。

### 3. 纯直线路由全链路 + 树优先分层布局
- **直线路由契约**：
  - 直线边统一写 `edge.type = 'straight'` 且 `edge.data.routingType = 'straight'`，清除折线 `waypoints`；`renderSpec` 按 `specEdge.routingType ?? n.edgeRouting ?? 'orthogonal'` 落盘；
  - 端口经 `distributeEdgePorts` 按子节点左右顺序沿父节点底边轻微错开（避免线上标签在起点拥挤），单入边落子节点顶边中点、多入边沿顶边错开。
- **共享树优先分层引擎（`packages/shared/src/render/tree-layout.ts`）**：
  - 抽出不依赖 `DiagramSpec` 的通用纯函数 `layoutTreeGraph(nodes, edges, options)`，供 `renderTree`、前端 `elk-layout.ts`、服务端 `diagram-auto-layout.ts` 三端共用：
    1. 忽略 `loop`/`annotate` 边计算最长路径层号 `depth(v)`；
    2. 单父子树按子树宽度居中对称展开；
    3. 多父共享/汇聚节点放在最深父层之下 `depth(v)` 行，X 坐标取所有父节点中心 X 的均值，再对同行节点做左右碰撞推开保持最小间距 `TREE_GAP`；
    4. `annotate` 贴宿主右侧放置并避让同行节点；`loop` 走侧向连接桩。
- **画布、模板与 MCP 同步**：
  - **图元面板**（`elements-panel.tsx`）：将 `pool` 拆出「横向泳道池 / 竖向泳道池」两个直拖/点击项，`flow-store.addNode('pool', pos, { orientation })` 直接创建对应方向泳道池；
  - **属性面板**（`property-panel.tsx`）：单选连线新增「连线路由（折线 / 直线）」切换，切直线清空 `waypoints`；
  - **自动排版**（`top-bar.tsx` + `elk-layout.ts` + MCP `auto_layout`）：新增 `mode?: 'layered' | 'tree'`（未传时服务端若 `meta.paradigm === 'tree'` 自动选 `'tree'`；对泳道图传 `'tree'` 安全回退泳道排版并告警）；前端在 `tree` 模式及直线边重排时同步调用 `distributeEdgePorts` 刷新端口并保持直线边无 `waypoints`；
  - **MCP `apply_ops`**：`connect` / `update_edge` / `insert_between` 支持 `routingType: 'orthogonal' | 'straight'`，同步更新 `MCP_TOOLS` 说明；
  - **模板库**（`presets.ts`）：新增「多端业务流转竖向泳道图」（客户端/服务端/业管端）与「接口全链路代码调用树」（`paradigm: 'tree'`、`edgeRouting: 'straight'`，含数据库/缓存/外部服务与汇聚节点）；
  - **导出兼容**：补齐 `standalone-html.ts` 对直线边与嵌套泳道的 SVG 世界坐标渲染。

## 五、自审拍板的 4 项技术决策
1. **含锁节点切向策略**：泳道池内只要存在 `position` 或 `full` 锁节点，切换方向（画布按钮或 MCP）整池拦截并提示，确保不产生半横半纵的损坏态；同方向重渲染仍保留人工拖动过的泳道位置。
2. **`tree` 放开边类型与破环策略**：`tree` 范式不再强制要求传 `kind: 'tree'`（省略即默认 `next`）；若代码中存在非 `loop` 有向环，破环分层但保留该连线并告警。
3. **横向单主干特例边界**：只有当横向泳道所有非附注节点（含 `branch`）都在同一条泳道时才走旧 `renderHorizontalTrunk`；一旦有跨泳道分支或主干，统一走新对称因果层号引擎。
4. **`auto_layout(mode: 'tree')` 三端统一引擎**：把树优先分层核抽成 `@flowstudio/shared` 纯函数，让 `scaffold_diagram`、MCP `auto_layout`、前端自动排版三端算法与端口刷新完全一致。
