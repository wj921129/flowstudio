# 设计方案：电路式全流程排版引擎、树状纯直线加固与 AI 模板体系

> 日期：2026-11-26 ｜ 状态：已实施（直接以 `circuit-flow` 替代 `vertical-flow`） ｜ 归类：`.work/dev/`

## 一、意图与背景（Why）

FlowStudio 在绘制复杂业务及代码级全流程（多路分流、嵌套判断、中途 `throw/return` 早退、`while/for` 循环、缺口附注）时，频发横纵方向错乱与元素乱飞，根因集中在 4 点：
1. 缺少单向全流程（严格自上而下 TD / 自左向右 LR）控制流引擎：`vertical-flow` 为“左竖主干 + 右侧二维网格”双轴混排，平级多路分支被硬拐 90° 横向甩出，左置附注飞入负坐标；
2. 拓扑序失真：`normalize.ts` 的分支 BFS 会吞噬未显式标 `role: 'main'` 的汇合下游主干，且 `mainOrder` / 破环 DFS 盲从 `nodes[]` 声明序；
3. 自动排版与增量协同无方向感：服务端/前端 `auto_layout`（ELK）默认 `RIGHT`、未剔除 `loop`/`annotate` 边；`inferBestSides` 仅按节点几何夹角选边；`apply_ops` 存在一字长蛇、未转局部坐标与顺推前误判端口；泳道同向重渲染锁死泳道坐标导致叠压；
4. 外部 AI 缺乏可直接参照的标准范式模板（MCP 工具收敛至 9 项后未提供模板读取通道与迷你样例）。

老板核心诉求与工作流：
- **心智模型**：代码/业务流程像电路图——入口与出口共主轴直线；遇 `if/else/switch/while` 在主轴上横向展开，每条分支内部保持纵向推进，同步骤起点齐平，汇合点对齐最复杂/最长分支底部后回归主轴；中途 `throw/return` 提前结束不汇入主分支；
- **分叉策略（老板已裁定：方式 A）**：单边守卫/早退保主轴直下、早退挂侧翼向下终结；平级多路分支水平齐平对称横展后再汇合；
- **路由与树状兼顾**：电路流同时兼容直角折线与纯直线，且加固现有纯直线树状图；
- **人机共治与模板**：MCP 完成主流程初始化，后续 MCP 与人工共同持续迭代；配套标准模板让 AI 一次理解并稳定出图。

## 二、目标 / 非目标 / 反目标

### 目标
1. 抽离三端共享拓扑预处理核 `packages/shared/src/render/topology.ts`，统一入口优先破环、边分离、连通分量切分与最长路径层号。
2. 新增一等范式 `circuit-flow` 及三端共享纯函数排版引擎 `layoutCircuitFlowGraph`（`circuit-flow-layout.ts` + `circuit-flow.ts`），精准落地方式 A 电路布局、横纵对称转置、纯直线防穿切列序、正坐标归一化与锁节点避让。
3. 加固现有 `tree-layout.ts` 纯直线树状引擎（入口优先破环、多父汇聚节点空间预留与推挤联动、`fixed` 锁节点避让、内层附注防掉底）。
4. 建立 3 层 AI 模板体系（SSOT `DIAGRAM_PRESETS` 新增 3 套电路标杆模板 + MCP 原生 `resources/list` & `resources/read` + Tool 描述与 Zod `.describe()` 内嵌选型口诀与黄金骨架），保持 9 个 MCP 工具不变。
5. 打通人机持续修改闭环：`auto_layout`（MCP + TopBar）支持 `mode: 'circuit' | 'layered' | 'tree'`、方向感知端口与 `meta` 同步回写；修复 `apply_ops`、泳道同向重渲染叠压与 A* 避障误罚自身泳道；升级 `diagram-inspector.ts` 几何与逆流软体检门禁。

### 非目标
- 不破坏既有 `vertical-flow`、`timeline-annotated`、`swimlane`、`tiered-dag`、`tree` 的历史契约与回归测试（含 `buildYeepaySpec`、`buildSvnSpec`、原 10 套预设的渲染测试）；
- 不新增第 10 个 MCP Tool（严守 9 工具精简契约，`mcp-tools.test.ts` 保持绿灯）；
- 不引入贝塞尔曲线路由；不做跨多泳道池联合排版。

### 反目标
- 严禁正向业务边逆流倒退、业务节点物理重叠或附注/节点飞入画布负坐标；
- 严禁 `circuit-flow` 依赖 `nodes[]` 声明顺序或省略 `role` 时发生主干被分支吞噬；
- 严禁纯直线模式下短支路斜向汇合线穿切中间早退节点，或点一次自动排版把纯直线图误洗成折线；
- 严禁破坏人类锚定锁（`position`/`full`）、AI 批次撤回或泳道人工留白间距（兼容 `spec-scaffold.test.ts`）。

## 五、核心设计

### 5.1 契约扩展与 `normalizeSpec`（`packages/shared/src/spec/`）
- **【自决】新增独立一等范式 `circuit-flow`**：`Paradigm` 扩展为 `'circuit-flow' | 'vertical-flow' | 'timeline-annotated' | 'swimlane' | 'tiered-dag' | 'tree'`，而非覆盖 `vertical-flow`——保证历史图与 `buildYeepaySpec`/`buildSvnSpec` 等既有测试 100% 零回归，同时在 MCP 引导中将 `circuit-flow` 确立为复杂业务/代码全流程首选范式。
- 复用 `DiagramSpec.orientation?: 'horizontal' | 'vertical'`（`swimlane` 默认 `'horizontal'`，`circuit-flow` 默认 `'vertical'`）与 `edgeRouting?: 'orthogonal' | 'straight'`（`circuit-flow` 默认 `'orthogonal'`）。
- `SpecNode` 新增可选 `earlyExit?: boolean`（显式标记中途 `throw/return` 提前结束节点；未填由引擎自动推导）；`apply_ops` 的 `add_node`/`update_node` 及 `CompactDiagram` 同步透传 `earlyExit`；`get_diagram` 的 `orientation` 支持从 `meta.orientation` 回退读回并新增回传 `edgeRouting`。
- `normalizeSpec` 针对 `circuit-flow`：
  - 接受 `next`/`branch`/`loop`/`jump`/`annotate`（省略默认 `'next'`）；
  - 不执行 `role` 冲突抛错，不执行分支 BFS 吞主干（仅将 `attachTo`/`annotate` 目标标为 `'annotation'`，其余保持业务节点）；
  - 允许 `annotate` 挂接任意业务节点并自动补齐缺失 `annotate` 边；仅禁自环，其余有向环由拓扑核入口优先破环并输出告警；
  - `mainOrder` 按正向 DAG 拓扑序产出。

### 5.2 统一拓扑预处理底座（`packages/shared/src/render/topology.ts`）
- 导出纯函数 `analyzeGraphTopology(nodes, edges)`：
  1. 分离业务节点与有效附注节点；分离正向候选边（排除 `loop`/`annotate`/自环）与显式回环边；
  2. 入口优先级排序：`inDegree === 0 && type === 'start-end'` > 其他 `inDegree === 0` > 显式/标签含入口语义 > 最小入度（同级保序）；
  3. 从优先入口集发起 DFS 识别未标 `loop` 的暗环 `backEdgeKeys`，产出无环正向邻接/父表、弱连通分量列表（主分量按规模降序 + 含入口优先）与最长路径层号 `layerOf`。
- `tree-layout.ts` 与 `swimlane.ts` 同步切换至 `analyzeGraphTopology`，根治按声明序破环致中游节点倒置首层的缺陷。

### 5.3 电路式控制流引擎（`packages/shared/src/render/circuit-flow-layout.ts` & `circuit-flow.ts`）
- 导出三端共享纯函数 `layoutCircuitFlowGraph(nodes, edges, opts)`，支持横纵对称转置：内核统一按逻辑纵轴（`main = 向下`，`cross = 横向`）计算；`direction === 'RIGHT'` 时对称交换节点宽高与输出坐标，并映射桩向 `top↔left`、`bottom↔right`。
- **【自决】正常延续子图上的后支配树 `ipdom(u)` 口径（防嵌套早退致 `ipdom` 退化）**：
  1. 预处理标记三类非主延续终点：① `loopTail`（去回环后出度 0 且拥有出向 `loop`/暗环回边的循环体尾节点）；② `hardEarlyExit`（显式 `earlyExit: true`）；③ `softEarlyExit`（仅当分量内存在其他正常主终态时，挂在分叉侧翼、无回边、短终态且含早退关键词 `失败/异常/驳回/报错/拒绝/拦截/超时/非法/跳过/缺口/throw/return/error/fail/reject` 或 `kind === 'branch'` 出度 0 叶子）。
  2. 仅将剩余正常出度 0 终态连向虚拟汇聚终点 `V_EXIT`（若全图均被标记则安全回退全连 `V_EXIT`）；沿 `V_EXIT` 反向可达求出「正常延续子图 `reachesExit`」，**仅在 `reachesExit` 子图上用 Cooper-Harvey-Kennedy 算法求 Immediate Post-Dominator `ipdom(u)`**。
  3. 如此即使外层分叉的某条支路内含 `throw/return` 早退或循环体，其外层正常汇合点 `m = ipdom(u)` 仍能精确锁定，绝不退化为 `V_EXIT`。
- **方式 A 盒式递归分解 `buildBox(start, stopNode)`**：
  - 每个子盒返回 `{ width, height, axisOffset, placements }`（`axisOffset` 为主轴距盒左缘偏移）；顺序节点沿 `axisOffset` 纵向递增 `MAIN_GAP`（50px）。
  - 遇分叉节点 `u`（正向出度 ≥ 2）及其作用域内汇合点 `m = ipdom(u)`，将出边归为 4 类：直通 `m` 空支路、循环体支路（尾有回边指回 `u`/祖先且不在 `reachesExit`）、早退支路（不在 `reachesExit` 且无回边）、常规并行支路（在 `reachesExit` 中）：
    - **形态 1（单边守卫 / 早退 / `while` 循环）**：常规 + 直通合计 = 1 且含早退或循环体 → 唯一主路锁在 `u` 的 `axisOffset` 直下；早退/循环体排在右侧，起点与主路下一步**同一水平线齐平**，内部递归纵向走完独立终结（早退不回连主干，侧翼按 `sideOccupiedY` 避让防后继早退碰撞；循环体尾走外侧回流通道回指 `u`；直通 `m` 的单边 `if (cond) { body }` 其汇合点 `m` 位于 `max(u底, body底) + MAIN_GAP` 回到中轴）。
    - **形态 2（平级多路 `if/else` / `switch`）**：常规支路 ≥ 2 → 所有支路起点在 `u` 下方**同一水平线横排**，各自内部递归构盒（支持无限层嵌套）；汇合支路组以 `u` 的 `axisOffset` 对称居中，早退支路列放最外侧；汇合点 `m`（若为真实节点）置于所有汇合支路最大底部之下 `MAIN_GAP` 处精确回归主轴。
  - **非严格 SPG 子集共享节点兜底**：同一分叉域 `[u .. m)` 内被 ≥2 条但非全部兄弟支路共享的局部汇聚节点（如多条异常支路共用同一“人工重出兜底”节点），先将共享它的兄弟支路排为相邻列，再将该共享子图抽出置于对应父支路最大底部之下并居中于父支路跨度内，确保每节点仅落位一次、零重叠。
- **纯直线（`straight`）防穿切规则**：
  - 同一分叉内：早退支路一律放最外侧，需汇合支路放内侧并按高度“短靠内、长靠外”排布，避免短支路斜直线汇合时穿切中间早退或长支路；
  - `loop` 回环边与跨 ≥2 层且起终点共轴的 `jump` 旁路边，单边自动保持 `routingType: 'orthogonal'` 走外侧通道，其余顺序/分叉/汇合边保持无 `waypoints` 纯直线。
- **正交总线、外侧通道、附注与正坐标归一化**：
  - `orthogonal` 模式下分叉/汇合输出干净水平总线 `waypoints`；`loop`/`jump` 在所属盒或全图外侧递增分配独立通道 `corridorX = outerRight + LOOP_SIDE + idx * REG_LANE_STEP`；
  - `annotate` 附注贴宿主外侧（优先左侧，碰撞避让）；全图落位后统一平移所有未锁定节点与 `waypoints` 至 `minX >= origin.x` 且 `minY >= origin.y`（根治负坐标飞出）；
  - `fixed` 锁定节点坐标零改写，未锁节点若与 `fixed` 碰撞则自动退让。

### 5.4 `tree-layout.ts` 纯直线树状引擎加固
- 接入 `analyzeGraphTopology` 入口优先破环；
- 按层自上而下排布，完成上层同行碰撞推挤后再用最新父中心坐标重算下层 `sharedIds` 多父汇聚节点 `idealCx`，对其及后代子树同步执行同行防撞推挤，消除多父子树压盖与父子漂移；
- 同行推挤遇 `fixed` 锁节点时将碰撞项跨过 `fixed.x + fixed.width + hGap`，不再 `continue` 撞穿；
- 内层节点附注放右侧碰撞时优先尝试左侧空位，再向下避让，防附注掉到树底。

### 5.5 方向感知端口分摊 & A* 避障修复
- `packages/shared/src/edge-port-allocator.ts`：`distributeEdgePorts` / `pickEdgePortsForConnect` 新增可选 `flowDirection?: 'DOWN' | 'RIGHT'`，传入时正向边锁主轴端口（`DOWN` 用 `bottom→top`，`RIGHT` 用 `right→left`），不再因跨列宽图 `|dx| > |dy|` 被改道，同侧多边仍按对端坐标有序错开。
- `packages/web/src/features/canvas/custom-edges/`：`RouteEdgeParams` 透传源/目标祖先容器 ID（`selfContainerIds`），A* 路由对自身所属泳道/泳池豁免 `laneCorridorPenalty`；`maxIterations` 提升至 `1200`、障碍搜索边距扩至 `240`。

### 5.6 3 层 AI 模板体系（保持 9 工具不变）
1. **SSOT 模板资产（`packages/shared/src/spec/presets.ts`）**：保留既有 10 套预设，新增 3 套 `flowchart` 标杆模板（总数 13，画布模板库自动实时渲染缩略图）：
   - `flowchart-circuit-code`（纵向直角：唯一入口 → 守卫早退 → 可选审核汇合 → 双通道并行含子判断与子集共享兜底 → `while` 重试回环 → 附注 → 唯一出口）；
   - `flowchart-circuit-straight`（纵向纯直线：演示早退外置与无穿切直线汇合）；
   - `flowchart-circuit-horizontal`（横向 LR 电路控制流）。
2. **【自决】MCP 原生 Resources 通道（`packages/server/src/mcp/mcp-server.ts`）**：保持 9 个 MCP Tools 不变，`initialize` 声明 `capabilities: { tools: {}, resources: {} }`，实现 `resources/list` 与 `resources/read`：
   - `flowstudio://guide/ai-drawing`：极简 AI 绘图决策卡与防错清单；
   - `flowstudio://templates/<presetId>`：动态返回 `DIAGRAM_PRESETS` 对应完整 `DiagramSpec` JSON。
3. **Tool 描述与 Schema 自描述增强**：为 `spec-schema.ts` / `op-schemas.ts` 关键字段补全中文 `.describe()`（保持 `add_node` 覆盖全量 21 种 `FLOW_NODE_TYPES` 遵守 `op-schemas-contract.test.ts`）；在 `scaffold_diagram` 描述内嵌范式选型口诀 + 紧凑版 `circuit-flow` 与 `tree(straight)` 黄金迷你骨架并引导读取 Resources；在 `apply_ops` 描述明确“初始化复杂整图禁用 `apply_ops`，仅用于局部增量编辑，结构变动大后调 `auto_layout` 收拢”。

### 5.7 人机协同迭代闭环与缺陷修复
- **【自决】`auto_layout` / `TopBar` 的 `edgeRouting` 推导与 `meta` 双向同步回写**：
  - `autoLayoutInputSchema`（同步补齐 `agentName`）与前端 `LayoutOptions` 扩展 `mode?: 'circuit' | 'layered' | 'tree'` 及可选 `edgeRouting?: 'orthogonal' | 'straight'`；
  - `edgeRouting` 未传时按「`meta.edgeRouting` → 非 `loop`/非 `annotate` 业务边 `straight` 占比 > 50% 判 `'straight'` → 默认 `'orthogonal'`」推导，且仅在显式传 `edgeRouting` 或纯直线回环/共轴 `jump` 例外时改写单边 `routingType`，绝不把纯直线图误洗成折线；
  - 扩展 `YjsDiagramBridge` 与 `useFlowStore` 轻量同步 `meta.paradigm`、`meta.orientation`、`meta.edgeRouting`；当用户通过 TopBar 或 AI 通过 `auto_layout` 显式改变方向/模式时，在同一 Yjs 事务中回写 `meta.orientation`（非泳道图切 `'circuit'`/`'tree'` 同步回写 `meta.paradigm`），保证 `diagram-inspector` 与后续 `apply_ops` 永远与当前画布对齐；
  - `mode` 未传时：`meta.paradigm === 'circuit-flow'` 默认 `'circuit'`，`'tree'` 默认 `'tree'`，其余 `'layered'`；`direction` 未传时依据 `meta.orientation` / `meta.paradigm`（`circuit-flow`/`vertical-flow`/`timeline-annotated`/`tiered-dag`/`tree` 与竖向泳池均默认 `DOWN`，仅横向泳池默认 `RIGHT`）；
  - 前端 `TopBar` 下拉新增「电路流排版（纵）」与「电路流排版（横）」；ELK `layered` 分支补齐 `loop`/`annotate` 过滤、核心 `layoutOptions` 与非泳道锁节点避让，清除自动边旧 `waypoints`。
