# MCP 智能连线锚点分摊与虚线扩展设计

> 日期：2026-11-25  
> 状态：已实现并验收（`pnpm test` 87 文件 / 521 用例全绿）

---

## 一、背景与目标

### 1.1 现状与断点
1. **画布前端与共享层已完备**：
   - 任意点锚点：`packages/shared/src/border-anchor.ts` 已支持 `side@offset`（`offset ∈ [0.04, 0.96]`）解析、格式化、几何边界投影（`getShapeBorderNormalizedPoint`、`getBorderAnchorWorldPoint`）；前端 `base-node-wrapper.tsx` 动态挂载 `customAttachedHandles`。
   - 线型渲染：`packages/shared/src/constants.ts` 定义 `EDGE_STROKE_STYLES`（`solid` / `dashed` / `dotted`）及 `getEdgeDashArray`；前端 `orthogonal-edge.tsx` 完整支持 `data.style.strokeStyle` 渲染。
2. **MCP 侧存在三处断点**：
   - **`scaffold_diagram`（主画图入口）**：`spec-schema.ts` / `spec/types.ts` 的边模型无 `strokeStyle` 与 `sourceHandle` / `targetHandle`；5 套范式渲染器（`vertical-flow` / `vertical-flow-grid` / `timeline-annotated` / `swimlane` / `tiered-dag` / `tree`）全部只使用四边中点（`top`/`right`/`bottom`/`left`），同节点同侧多条连线会完全重叠，且 A↔B 双向边直接重合。
   - **`apply_ops`（增量编辑）**：`op-schemas.ts` 虽用正则接收 `borderHandleSchema`，但未校验 `offset` 语义区间、工具描述未告知 AI 线型与锚点规范；`op-executor.ts` 的 `connect` 与 `insert_between` 在未传 handle 时直接留空（落入默认中点），不做智能选边与防重叠；`get_diagram` / `search_nodes`（`ai-collaborator.ts`）未回传连线 `strokeStyle`。
   - **`auto_layout`（服务端自动排版）**：`diagram-auto-layout.ts` 只重算节点坐标，不刷新连线锚点，排版后易导致边绕行或同侧重叠。

### 1.2 核心目标
- **友好连线防重叠**：AI 画流程图与增量加边时，无需手工算坐标偏移即可自动避开同侧同点重叠并拆分双向重合边；同时保留人工或 AI 显式指定的 `side@offset` 精调入口。
- **线型语义对齐**：将 `solid` / `dashed` / `dotted` 完整打通至 MCP 生成、增量、读取、自动排版与语义巡检全链路。

  - 不修改前端 `orthogonal-edge.tsx`、`edge-routing-manager.ts`、`base-node-wrapper.tsx` 交互逻辑；

## 四、详细设计

### 4.1 共享端口分摊引擎（`packages/shared/src/edge-port-allocator.ts`）

新建纯函数模块并在 `packages/shared/src/index.ts` 导出，作为全图生成、增量连线与自动排版的唯一端口计算核心。

#### 4.1.1 基础几何工具
1. **`resolveNodeWorldBoxes(nodes: readonly FlowNode[]): Map<string, NodeWorldBox>`**
   - `NodeWorldBox = { id: string; type: string; x: number; y: number; width: number; height: number }`。
   - 沿着 `node.parentId` 向上累加祖先 `position` 得到世界坐标，使用 `visited` 集合防止异常父子环。
   - 若 `width` / `height` 缺失或 `<= 0`，回退至 `getDefaultNodeSize(node.type)`（`packages/shared/src/node-registry.ts`）。
2. **`getSafeOffsetRange(nodeType: string | undefined, count: number): [number, number]`**
   - `decision`（菱形顶点在 `0.5`，边角收缩）：默认 `[0.2, 0.8]`；`count > 5` 放宽至 `[0.12, 0.88]`；
   - `start-end` / `database`（圆角/椭圆收口）：默认 `[0.18, 0.82]`；`count > 5` 放宽至 `[0.1, 0.9]`；
   - 其他节点类型：默认 `[0.15, 0.85]`；`count > 5` 放宽至 `[0.08, 0.92]`。
3. **`inferBestSides(sourceBox: NodeWorldBox, targetBox: NodeWorldBox): { sourceSide: BorderSide; targetSide: BorderSide }`**
   - 若 `sourceBox.id === targetBox.id`（自环）：返回 `{ sourceSide: 'right', targetSide: 'top' }`；
   - 计算中心向量 `dx = targetCenterX - sourceCenterX`、`dy = targetCenterY - sourceCenterY`；
   - `|dx| >= |dy|` 时：若 `dx >= 0` 则 `right -> left`，否则 `left -> right`；
   - `|dx| < |dy|` 时：若 `dy >= 0` 则 `bottom -> top`，否则 `top -> bottom`。

#### 4.1.2 全图均匀分摊：`distributeEdgePorts(nodes, edges, options?)`
用于 `renderSpec` 全图生成与 `auto_layout` 排版收敛。

- **输入选项**：
  - `fixedEdgeIds?: ReadonlySet<string>`：完全受保护的边（如连接锁定节点的边），两端锚点保持不变，但仍作为“已占偏移”参与同侧避让；
  - `lockedSourceEdgeIds?: ReadonlySet<string>` / `lockedTargetEdgeIds?: ReadonlySet<string>`：仅固定对应端（如 `SpecEdge` 显式传入了 `sourceHandle` 或 `targetHandle`，或已有边手调过精确 `side@offset`）；
  - `obstacleEdges?: ReadonlyArray<Pick<FlowEdge, 'id' | 'source' | 'target' | 'sourceHandle' | 'targetHandle'>>`：不参与本次结果修改、但需在分桶时作为只读固定占位参与同侧偏移避让的既有保护边（用于 `scaffold_diagram` 存在单端/双端 `full` 锁定旧边时避免新边撞点）。
- **分桶逻辑**：
  - 以 `(nodeId, side)` 为键收集所有端点（**同时包含出边与入边**）。
  - *效果*：若 A→B 与 B→A 共用 A 的 `right` 侧、B 的 `left` 侧，两条边进入同一个 `(nodeId, side)` 桶并自然分摊到不同 offset，彻底拆开双向重合边。
  - 若某条边未设置 `sourceHandle` / `targetHandle`（或其 side 无效），先按 `inferBestSides` 补全侧向再入桶。
- **防交叉排序规则**：
  - 对每个 `(nodeId, side)` 桶内端口按对端节点中心坐标升序排序：
    - `side` 为 `'top'` 或 `'bottom'`：按对端中心 `x` 升序；
    - `side` 为 `'left'` 或 `'right'`：按对端中心 `y` 升序；
  - 若对端中心坐标相同（含多条平行边或双向边）：出边（`isSource`）排在入边前，同向再按 `edge.id` 字典序稳定排序。
- **槽位分配算法**：
  - 设桶内“固定端”偏移集合为 `fixedOffsets`，“待分配端”数量为 `m`（总条数 `total = fixedOffsets.length + m`）：
    - **纯自动分配（`fixedOffsets.length === 0`）**：
      - `m === 1`：`[0.5]`（经 `formatBorderAnchorHandle` 输出纯 `'top'|'right'|'bottom'|'left'`，兼容旧格式）；
      - `m === 2`：`[1/3, 2/3]`（若超出该节点类型 `getSafeOffsetRange`，回退等距计算）；
      - `m === 3`：`[0.25, 0.5, 0.75]`（同上校验安全区间）；
      - `m >= 4`：在 `[min, max] = getSafeOffsetRange(nodeType, m)` 内等距分布：`min + (max - min) * i / (m - 1)`。
    - **混合共存（`fixedOffsets.length > 0`）**：
      - 固定端保持原 `handle` 不动；
      - 对每个待分配端先按其理想等距目标位置 `min + (max - min) * rank / Math.max(1, total - 1)` 排位，再与 `fixedOffsets` 及已占位置做冲突检测（碰撞阈值 `0.08`）：若冲突，在安全区间 `[min, max]` 内沿剩余最大连续空隙中点或最近无碰撞位置落位；
      - 最终将分配后的 `offset` 传入 `formatBorderAnchorHandle(side, offset)`。
- **`waypoints` 首尾段联动校准**：
  - 仅当某条边**至少有一端发生锚点变化**且 `edge.data?.waypoints?.length > 0` 时执行：
  - 使用 `getBorderAnchorWorldPoint(sourceBox, newSourceHandle, sourceSide, sourceBox.type)` 与 `getBorderAnchorWorldPoint(targetBox, newTargetHandle, targetSide, targetBox.type)` 得到精确世界坐标 `sPt`、`tPt`。
  - 校准首点 `waypoints[0]`（保持首段与离开方向一致的正交延伸）：
    - 若 `sourceSide` 为 `'left'` 或 `'right'`，令 `waypoints[0] = { x: waypoints[0].x, y: sPt.y }`；
    - 若 `sourceSide` 为 `'top'` 或 `'bottom'`，令 `waypoints[0] = { x: sPt.x, y: waypoints[0].y }`。
  - 校准尾点 `waypoints[last]`（仅当 `waypoints.length >= 2` 时按同样规则分别对齐 `tPt`，若 `waypoints.length === 1` 则优先对齐首段变化端，避免单拐点失去正交性：对于渲染器中存在的 2 点 `jump`/`annotate` 及 3~4 点 `loop`/`regression`，均有 `>= 2` 个点，首尾分别对齐即可天然保持全程正交）。
  - *纯度保证*：不原地修改入参 `edges`，返回新数组。

#### 4.1.3 增量空位避让：`pickEdgePortsForConnect(nodes, existingEdges, params)`
用于 `apply_ops.connect` 与 `apply_ops.insert_between`（**严格遵循方案 B：只挑新边空位，绝不改已有边**）。

- **输入**：`nodes`、`existingEdges`、`params: { sourceId, targetId, sourceHandle?, targetHandle? }`。
- **侧向决定**：
  - 若 `params.sourceHandle` 存在，解析其 `side` 与是否自带 `@offset`（若显式带 `@offset` 或为显式传入的精确 handle，**直接原样采用**，见下方说明）；
  - **显式 handle 语义约定**：
    - `params.sourceHandle` 未传 → 自动推算最优 `side` + 自动挑空闲 `offset`；
    - `params.sourceHandle` 传入纯方向（如 `'right'`）→ 锁定使用 `'right'` 侧，**仍在 `'right'` 侧自动避让已有锚点**（避免 AI 只指定方向仍撞车）；
    - `params.sourceHandle` 传入精确锚点（如 `'right@0.25'`）→ **严格保留** `'right@0.25'`，不做改动。
    - `targetHandle` 同理。
- **同侧空位挑选算法**：
  1. 收集目标节点 `nodeId` 在选定 `side` 上所有 `existingEdges`（出边 + 入边）占用的 `offset`（通过 `parseBorderAnchorHandle` 解析，纯 `side` 计为 `0.5`）。
  2. 计算安全区间 `[min, max] = getSafeOffsetRange(nodeType, occupied.length + 1)`。
  3. 冲突判定阈值 `PORT_COLLISION_GAP = 0.08`：某候选 `c` 若与任意已有偏移距离 `< 0.08` 则视为冲突。
  4. 候选优先级：
     - 首选 `0.5`（若无冲突直接返回 `side`）；
     - 其次按“贴近对端投影方向”排序的友好刻度集合 `[0.25, 0.75, 1/3, 2/3, 0.2, 0.8, 0.15, 0.85]`（筛选在 `[min, max]` 内的值）：先计算对端中心沿垂直轴相对当前节点盒子的归一化投影 `ideal`（`clamp(t, min, max)`），对无冲突刻度按 `|c - ideal|` 升序挑选（同等距离按更接近 `0.5` 优先）；
     - 若友好刻度全部冲突，将 `[min, ...sortedOccupied, max]` 分割为区间段，取**最大空隙的中点**（并钳位在 `[min, max]`）；极端密集全满时回退 `ideal`。
  5. 若同一批 `connect` 连续添加多条边：调用方每创建一条边，该边立即进入后续边的 `existingEdges`（在 `executeApplyOps` 中直接把新建边追加进当前上下文或读取实时 `edgesMap`），天然做到同批连加也互不重叠。

### 4.2 虚线与线型契约（`strokeStyle`）

#### 4.2.1 语义默认规则（已确认选项 1）
- 支持枚举：复用 `@flowstudio/shared` 现有常量 `EDGE_STROKE_STYLES = ['solid', 'dashed', 'dotted']`。
- 唯一隐式默认：当 `kind === 'annotate'` 且未显式指定 `strokeStyle`（包括顶层 `strokeStyle` 与 `style.strokeStyle`）时，默认写入 `data.style.strokeStyle = 'dashed'`；其余 `kind` 默认 `'solid'`（保持不强制写入冗余字段，仅在显式指定或 `annotate` 时落入 `data.style.strokeStyle`，`get_diagram` 输出未设时可视为 `'solid'` 或省略，`update_edge` 显式传入 `'solid'` 时允许覆盖取消虚线）。

#### 4.2.2 Schema 与类型扩展
1. **`packages/shared/src/types.ts` & `schemas/diagram-schema.ts`**：
   - `FlowEdgeData` 新增两个只读指纹可选字段（`.passthrough()` 已兼容，同步补齐接口与 `flowEdgeDataSchema` 定义）：
     - `autoSourceHandle?: string`
     - `autoTargetHandle?: string`
   - **指纹写入规则（用于在不修改前端拖拽代码的前提下精准区分“系统自动分摊”与“人工手调 / AI 显式精确指定”）**：
     - 当 `renderSpec`、`apply_ops.connect`、`insert_between` 或 `auto_layout` 为某端自动计算并写入锚点时，同步将该结果写入 `data.autoSourceHandle` / `data.autoTargetHandle`；
     - 当 AI 显式传入精确 `side@offset`（如 `connect` / `update_edge` / `SpecEdge`）时，**不写入或清除**对应端的 `auto*Handle` 指纹；
     - 前端 `orthogonal-edge.tsx` / `flow-store.ts` 人工重连端点时仅修改 `edge.sourceHandle` / `edge.targetHandle`，不修改 `data.auto*Handle`，从而天然产生指纹失配。
2. **`packages/shared/src/spec/types.ts` & `spec-schema.ts`**：
   - 新增 `borderHandleSpecSchema = z.string().regex(/^(top|right|bottom|left)(@(\d+(?:\.\d+)?))?$/)` 并在 `.refine` 中校验可选数值在 `[0.04, 0.96]`（或给出清晰报错）；
   - `SpecEdge` / `specEdgeSchema` 新增可选字段：
     - `strokeStyle?: EdgeStrokeStyle`（`z.enum(EDGE_STROKE_STYLES).optional()`）
     - `sourceHandle?: string`
     - `targetHandle?: string`
   - `normalizeSpec` 原样透传上述字段（不做阻断，仅校验枚举与正则）。
2. **`packages/server/src/mcp/op-schemas.ts` & `types.ts`**：
   - `borderHandleSchema`：将原本只做正则校验的 `^(top|right|bottom|left)(@\d+(\.\d+)?)?$` 升级为同时校验可选偏移值 `∈ [0.04, 0.96]`（带清晰中文提示）。
   - 新增 `edgeStyleSchema = z.object({ strokeColor: z.string().optional(), strokeWidth: z.number().positive().max(20).optional(), strokeStyle: z.enum(EDGE_STROKE_STYLES).optional(), animated: z.boolean().optional() }).passthrough()`。
   - `connect` 与 `update_edge` 的 op Schema：
     - `style: edgeStyleSchema.optional()`
     - 同时新增顶层便捷字段 `strokeStyle: z.enum(EDGE_STROKE_STYLES).optional()`（降低 AI 传参嵌套出错率）；合并规则：**顶层 `strokeStyle` 优先于 `style.strokeStyle`**，最终统一落库到 `edge.data.style.strokeStyle`（确保与前端 `orthogonal-edge.tsx` 单一真相源一致）。
   - `insert_between` 的 op Schema：新增可选 `strokeStyle: z.enum(EDGE_STROKE_STYLES).optional()`（未传时继承被断开原边的 `data.style`）。

### 4.3 MCP 全链路集成改造

#### 4.3.1 `renderSpec` 统一出口（`packages/shared/src/render/index.ts`）与 `executeScaffoldDiagram`
1. `RenderOptions`（`packages/shared/src/render/types.ts`）新增可选字段：
   - `protectedEdges?: ReadonlyArray<FlowEdge>`（由 `executeScaffoldDiagram` 传入：包含与 `protectedIds`（`full` 锁定节点及其祖先）单端或双端相连的既有边）。
2. 在各个范式渲染器执行完毕后，于 `renderSpec` 返回前统一做两步后处理：
   - **样式、显式锚点与保护边合入**：遍历 `n.edges` 与已生成的 `result.edges`：
     - 若某条生成边匹配 `protectedEdges` 中连向 `full` 锁定节点的既有边（按 `edgeKey` 匹配）：恢复该既有边的 `sourceHandle` / `targetHandle` 并将其加入 `fixedEdgeIds`，保证渲染规划视角与 `diffRendered` 实际跳过逻辑一致；
     - 未被整条锁定的边中，若 `SpecEdge` 显式传入 `sourceHandle` / `targetHandle`：覆盖对应端（若是精确 `side@offset` 则加入 `lockedSourceEdgeIds` / `lockedTargetEdgeIds` 保护，且不写对应 `auto*Handle`；若是纯 `side` 则作为约束侧向参与均匀分摊）；
     - 确定 `strokeStyle = e.strokeStyle ?? (e.kind === 'annotate' ? 'dashed' : undefined)`，若存在则合并至 `edge.data.style`。
   - **全图端口分摊**：将不在 `Spec` 中但双端受保护的 `protectedEdges` 作为 `obstacleEdges` 传给 `distributeEdgePorts(result.nodes, result.edges, { fixedEdgeIds, lockedSourceEdgeIds, lockedTargetEdgeIds, obstacleEdges })`，一次性为 5 套范式（含 `vertical-flow` / `vertical-flow-grid` / `timeline-annotated` / `swimlane` / `tiered-dag` / `tree`）自动拆开同侧多连线与双向边、避开锁定节点既有旧边端口、联动校准 `waypoints`，并为自动分配端写入 `data.autoSourceHandle` / `data.autoTargetHandle` 指纹。

#### 4.3.2 `diffRendered`（`packages/server/src/mcp/spec-ops.ts`）
- 当前 `diffRendered`（L72）：`const data = { ...(ex.data as object), ...(re.data as object) };` 是浅合并 `data`，若 `ex.data.style` 原本有 `{ strokeColor: '#ef4444' }` 而 `re.data.style` 有 `{ strokeStyle: 'dashed' }`，浅合并会直接覆盖丢失 `strokeColor`！
- **改造**：对 `data.style` 做嵌套合并：`mergedStyle = { ...(exStyle ?? {}), ...(reStyle ?? {}) }`；且当 `re` 不再指定 `strokeStyle`（例如用户或 Spec 把 `dashed` 改回默认实线）时，若 `exStyle?.strokeStyle` 存在则显式清理或设为 `'solid'`（按 `re.data.style` 是否显式设 `'solid'` 决定：Spec 中若未传 `strokeStyle` 且非 `annotate`，`reStyle` 不含 `strokeStyle`，对于曾经由 Spec 生成并已存在 `exStyle.strokeStyle` 的非锁定边，若 Spec 为非 `annotate` 且未传 `strokeStyle`，应重置为 `'solid'` 或删除 `strokeStyle` 键，以保证反复调用 `scaffold_diagram` 改回实线能生效）。

#### 4.3.3 `op-executor.ts`（`apply_ops` 执行器）
1. **构建实时视图辅助函数**：`snapshotGraphForPortPicking(nodesMap, edgesMap)`，直接从当前 `Y.Doc` 的 `nodesMap` 和 `edgesMap` 生成 `FlowNode[]` 与 `FlowEdge[]` 快照（确保同一个 `apply_ops` 事务内前序 `add_node` / `move_node` / `connect` / `disconnect` 的结果立即可被后续 `connect` 感知）。
2. **`connect`**：
   - 解析有效 `strokeStyle = op.strokeStyle ?? op.style?.strokeStyle ?? (op.kind === 'annotate' ? 'dashed' : undefined)`；
   - 合并 `finalStyle = { ...(op.style ?? {}), ...(strokeStyle ? { strokeStyle } : {}) }`；
   - 调用 `pickEdgePortsForConnect(currentNodes, currentEdges, { sourceId: op.source, targetId: op.target, sourceHandle: op.sourceHandle, targetHandle: op.targetHandle })` 得到 `{ sourceHandle, targetHandle }`；
   - 若某端未传精确 `side@offset`（即由服务端自动选位），将结果同步写入 `data.autoSourceHandle` / `data.autoTargetHandle`；若显式传了精确 `side@offset` 则不写对应端指纹；
   - 创建边写入 `edgesMap`（**不修改任何已有边**）。
3. **`update_edge`**：
   - 支持合并 `op.strokeStyle`（优先）与 `op.style` 到 `nextData.style`；
   - 若显式传入精确 `sourceHandle` / `targetHandle`（`side@offset`），清除对应端 `nextData.autoSourceHandle` / `nextData.autoTargetHandle`；若更新了锚点且当前边存在 `nextData.waypoints`（数组长度 >= 1），调用锚点世界坐标校准辅助函数同步调整 `waypoints` 首尾点。
4. **`insert_between`**：
   - 在删除 `originalEdgeIds` 前，提取首条匹配原边的 `data.style`（若无则为空）；若 `op.strokeStyle` 存在则覆写 `strokeStyle`；
   - 删除原边后，新建的两条边（`source -> newNode` 与 `newNode -> target`）均通过 `pickEdgePortsForConnect` 选取无重叠端口（并尊重 `op.direction` 作为默认侧向偏好参考：若在同行/同列，自然导出 `right/left` 或 `bottom/top`），同步记录 `data.autoSourceHandle` / `data.autoTargetHandle`，并继承样式。

#### 4.3.4 `diagram-auto-layout.ts`（`auto_layout` 锚点联动）
- **时机**：在 `executeAutoLayout` 的 `ctx.writer.mutate` 事务中，所有 `pool`、`lane`、普通节点的新坐标与尺寸写入 `nodesMap` **之后**。
- **保护边界（精准区分人工精调与自动锚点）**：
  - 定义单端“可刷新”判定函数 `isAutoManagedPort(handle, autoFingerprint)`：
    - 若 `handle` 为空，或 `parseBorderAnchorHandle(handle)` 为中点（`Math.abs(offset - 0.5) < 0.002`）：**可刷新**（兼容历史无指纹数据）；
    - 若 `autoFingerprint` 存在且 `handle === autoFingerprint`：**可刷新**（系统曾自动分摊且未被人工或 AI 改过，支持切换 `RIGHT`/`DOWN` 方向后重新选侧与分摊）；
    - 否则（存在非中点精确 `side@offset` 且与指纹不匹配或无指纹）：**视为人工手调或 AI 显式指定，保留不动**。
  - 遍历 `edgesMap`：
    1. 若源或目标节点被锁定（`lockedIds.has(...) || frozenIds.has(...)`）：整条边加入 `fixedEdgeIds`，保持原样；
    2. 对未锁定边的源端与目标端分别应用 `isAutoManagedPort`：保留不可刷新端并加入 `lockedSourceEdgeIds` / `lockedTargetEdgeIds`；对可刷新端清除旧侧向绑定以按新坐标重新执行 `inferBestSides` + `distributeEdgePorts`；
    3. 仅当两端均被刷新且边原本未人工设定特殊拐点时清除旧失效 `waypoints`（若任一端被保留且存在 `waypoints`，仅在刷新端联动校准首/尾点）。
  - 对自动刷新后的端口更新 `data.autoSourceHandle` / `data.autoTargetHandle`；将所有发生变更的字段按 `recordUpdate('edge', ...)` 计入同一 `ai-layout` 批次 `diffs`，支持 `undo_ai_batch` 整体/单点撤回。

## 五、边界条件与留给实施阶段的约定

1. **越界与非法值处理**：
   - MCP Zod Schema 层对显式传入的 `side@offset` 严格校验 `0.04 <= offset <= 0.96`，避免 AI 传入 `right@2.5` 被静默钳位而产生误解；
   - 共享分摊引擎 `edge-port-allocator.ts` 内部仍对所有计算/读取结果调用 `clampBorderOffset` 与 `formatBorderAnchorHandle` 兜底。
2. **默认约定（Builder Check 可直接沿用）**：
   - 节点缺少 `width`/`height` 时按 `getDefaultNodeSize(type)` 兜底；
   - 两条边同侧分布优先 `1/3`、`2/3`（经 `formatBorderAnchorHandle` 为 `side@0.3333`、`side@0.6667`，恰好命中画布前端 `BORDER_SNAP_OPTIONS` 的 `1/3`、`2/3` 刻度）；三条边优先 `0.25`、`0.5`、`0.75`（命中 `1/4`、`1/2`、`3/4` 刻度）。
   - `diffRendered` 中同 `(source, target, kind)` 若存在多条并行边目前以 `edgeKey` 为键，维持现有语义不扩大改造范围。
   - 内部辅助函数命名、测试文件组织方式（复用既有 `packages/shared/tests/` 与 `packages/server/tests/`）由实施阶段自行决定。
